## Overview

This plan outlines the implementation of **Agentic Chunking** in the Hazina framework - an intelligent, LLM-powered approach to document segmentation that:

- Uses AI to identify natural semantic boundaries
- Maintains topic coherence within chunks
- Generates rich metadata for each chunk
- Produces variable-sized chunks optimized for retrieval
- Adapts to document structure and content type

**Benefits over current chunking:**
- ✅ Better semantic coherence (chunks represent complete ideas)
- ✅ Improved retrieval accuracy (more relevant context per chunk)
- ✅ Adaptive to content type (code, prose, technical docs, etc.)
- ✅ Rich metadata generation (summaries, keywords, topics)
- ✅ Reduced chunk boundary artifacts (no mid-sentence splits)

## What is Agentic Chunking?

### Traditional Chunking (Current)
```
Document → Split at fixed size/sentence/paragraph → Chunks
```

**Problems:**
- Arbitrary boundaries often split semantic units
- No awareness of topic changes or logical structure
- Fixed sizes don't account for content complexity
- Metadata is basic (position, size only)

### Agentic Chunking (Proposed)
```
Document → LLM Analyzes Structure → Identifies Topics/Sections
    → Determines Optimal Boundaries → Variable-Sized Chunks
    → Generates Rich Metadata → Coherent Chunks
```

**Advantages:**
- Boundaries align with semantic shifts
- Each chunk represents a complete idea/topic
- Metadata includes summaries, keywords, relationships
- Chunk size varies based on content complexity
- Better retrieval through semantic coherence

### Example: Technical Documentation

**Traditional (Fixed 1000 chars):**
```
Chunk 1: "...The authentication system uses JWT tokens.
         Tokens are generated by the AuthService class which..."

Chunk 2: "...implements the IAuthProvider interface. The token
         lifetime is configurable. Database Configuration: The
         system uses PostgreSQL for..."  [TOPIC SHIFT MID-CHUNK]
```

**Agentic:**
```
Chunk 1 (Authentication):
  Content: "The authentication system uses JWT tokens. Tokens
           are generated by the AuthService class which implements
           the IAuthProvider interface. The token lifetime is
           configurable via appsettings.json."
  Metadata: {
    topic: "Authentication System",
    keywords: ["JWT", "AuthService", "IAuthProvider", "tokens"],
    summary: "JWT-based authentication using AuthService",
    sectionType: "TechnicalDescription"
  }

Chunk 2 (Database):
  Content: "Database Configuration: The system uses PostgreSQL
           for data persistence. Connection strings are managed..."
  Metadata: {
    topic: "Database Configuration",
    keywords: ["PostgreSQL", "connection strings"],
    summary: "PostgreSQL database setup and configuration",
    sectionType: "Configuration"
  }
```

```
[LLM Analysis Phase]
```

```csharp
public class AgenticChunker
{
    private readonly ILLMClient _llmClient;
    private readonly ILogger<AgenticChunker>? _logger;

    public AgenticChunker(ILLMClient llmClient, ILogger<AgenticChunker>? logger = null)
    {
        _llmClient = llmClient;
        _logger = logger;
    }

    public async Task<List<TextChunk>> ChunkAsync(
        string text,
        TextChunkingOptions options,
        CancellationToken ct = default)
    {
        // 1. Analyze document and get proposed boundaries
        var analysis = await AnalyzeDocumentStructureAsync(text, options, ct);

        // 2. Create chunks from boundaries
        var chunks = CreateChunksFromBoundaries(text, analysis.Boundaries);

        // 3. Optional: Enrich with metadata
        if (options.UseAgenticMetadata)
        {
            await EnrichChunksWithMetadataAsync(chunks, ct);
        }

        return chunks;
    }

    private async Task<ChunkingAnalysisResponse> AnalyzeDocumentStructureAsync(
        string text,
        TextChunkingOptions options,
        CancellationToken ct)
    {
        var prompt = ChunkingPromptBuilder.BuildAnalysisPrompt(text, options);

        var messages = new List<HazinaChatMessage>
        {
            new(HazinaMessageRole.System, "You are an expert at analyzing document structure."),
            new(HazinaMessageRole.User, prompt)
        };

        var response = await _llmClient.GetResponse<ChunkingAnalysisResponse>(
            messages,
            toolsContext: null,
            images: null,
            ct
        );

        return response.Result ?? throw new InvalidOperationException("LLM returned no chunking analysis");
    }

    private List<TextChunk> CreateChunksFromBoundaries(string text, List<ChunkBoundary> boundaries)
    {
        var chunks = new List<TextChunk>();

        for (int i = 0; i < boundaries.Count; i++)
        {
            var boundary = boundaries[i];
            var chunkText = text.Substring(boundary.Start, boundary.End - boundary.Start);

            chunks.Add(new TextChunk
            {
                Text = chunkText,
                Index = i,
                StartPosition = boundary.Start,
                EndPosition = boundary.End,
                Metadata = new Dictionary<string, object>
                {
                    ["boundary_reason"] = boundary.Reason,
                    ["chunking_strategy"] = "agentic"
                }
            });
        }

        return chunks;
    }

    private async Task EnrichChunksWithMetadataAsync(List<TextChunk> chunks, CancellationToken ct)
    {
        // Parallel metadata generation for all chunks
        var tasks = chunks.Select(chunk => EnrichSingleChunkAsync(chunk, ct));
        await Task.WhenAll(tasks);
    }

    private async Task EnrichSingleChunkAsync(TextChunk chunk, CancellationToken ct)
    {
        var prompt = ChunkingPromptBuilder.BuildMetadataPrompt(chunk.Text);

        var messages = new List<HazinaChatMessage>
        {
            new(HazinaMessageRole.System, "You extract metadata from text chunks."),
            new(HazinaMessageRole.User, prompt)
        };

        var response = await _llmClient.GetResponse<ChunkMetadataResponse>(
            messages,
            toolsContext: null,
            images: null,
            ct
        );

        if (response.Result != null)
        {
            chunk.Metadata["summary"] = response.Result.Summary;
            chunk.Metadata["keywords"] = response.Result.Keywords;
            chunk.Metadata["topic"] = response.Result.Topic;
            chunk.Metadata["section_type"] = response.Result.SectionType;
        }
    }
}
```

public static class ContentTypeDetector
{
    public static DocumentContentType Detect(string text)
    {
        // Heuristics:
        // - Check for code patterns (function definitions, brackets, semicolons)
        // - Check for markdown syntax (##, *, [], etc.)
        // - Check for JSON structure
        // - Default to prose

        if (text.Contains("```") || text.Contains("function ") || text.Contains("class "))

        if (text.Contains("## ") || text.Contains("### "))
            return DocumentContentType.Markdown;

        if (text.TrimStart().StartsWith("{") || text.TrimStart().StartsWith("["))
            return DocumentContentType.Json;

        return DocumentContentType.Prose;
    }
}

#### Step 2.3: Caching and Performance Optimization

**Problem:** LLM calls are slow and expensive for large documents

**Solution 1: Hierarchical Chunking**
```
Large Document (10K+ chars)
    ↓
Pre-split into sections (~2K chars each)
    ↓
Run agentic chunking on each section in parallel
    ↓
Merge results
```

**Implementation:**

```csharp
public async Task<List<TextChunk>> ChunkLargeDocumentAsync(
    string text,
    TextChunkingOptions options,
    CancellationToken ct)
{
    const int SECTION_SIZE = 2000;

    if (text.Length <= SECTION_SIZE)
    {
        return await ChunkAsync(text, options, ct);
    }

    // Pre-split into sections
    var sections = PreSplitIntoSections(text, SECTION_SIZE);

    // Process sections in parallel
    var chunkTasks = sections.Select((section, idx) =>
        ChunkSectionAsync(section, idx, options, ct)
    );

    var chunkResults = await Task.WhenAll(chunkTasks);

    // Merge and re-index
    return MergeChunks(chunkResults);
}
```

#### Step 2.4: Fallback and Error Handling

**Scenarios:**
1. LLM returns invalid boundaries
2. LLM call times out
3. LLM returns empty response
4. Chunk sizes violate constraints

**Implementation:**

```csharp
private async Task<ChunkingAnalysisResponse> AnalyzeDocumentStructureAsync(
    string text,
    TextChunkingOptions options,
    CancellationToken ct)
{
    try
    {
        var analysis = await CallLLMForAnalysis(text, options, ct);

        // Validate boundaries
        if (!ValidateBoundaries(analysis.Boundaries, text.Length, options))
        {
            _logger?.LogWarning("LLM returned invalid boundaries. Using fallback strategy.");
            return CreateFallbackBoundaries(text, options);
        }

        return analysis;
    }
    catch (OperationCanceledException)
    {
        throw; // Don't catch cancellation
    }
    catch (Exception ex)
    {
        _logger?.LogError(ex, "Agentic chunking failed. Falling back to {Strategy}",
            options.FallbackStrategy);
        return CreateFallbackBoundaries(text, options);
    }
}

private bool ValidateBoundaries(List<ChunkBoundary> boundaries, int textLength, TextChunkingOptions options)
{
    // Check: boundaries are sorted
    // Check: no overlaps
    // Check: within text bounds
    // Check: respect min/max sizes
    // Check: cover entire document

    for (int i = 0; i < boundaries.Count; i++)
    {
        var b = boundaries[i];

        if (b.Start < 0 || b.End > textLength || b.Start >= b.End)
            return false;

        if (b.End - b.Start < (options.MinChunkSize ?? 0))
            return false;

        if (b.End - b.Start > (options.MaxChunkSize ?? int.MaxValue))
            return false;

        if (i > 0 && b.Start < boundaries[i - 1].End)
            return false; // Overlap
    }

    return true;
}

private ChunkingAnalysisResponse CreateFallbackBoundaries(string text, TextChunkingOptions options)
{
    // Use simple paragraph-based chunking as fallback
    var paragraphChunker = new TextChunker();
    var chunks = paragraphChunker.ChunkByParagraph(text, options);

    var boundaries = chunks.Select(c => new ChunkBoundary
    {
        Start = c.StartPosition,
        End = c.EndPosition,
        Reason = "Fallback chunking (LLM unavailable)"
    }).ToList();

    return new ChunkingAnalysisResponse { Boundaries = boundaries };
}
```

```csharp
        {
            var keywords = (List<string>)metadata["keywords"];
            if (keywords.Any(k => query.Contains(k, StringComparison.OrdinalIgnoreCase)))
            {
                result.Score *= 1.2; // 20% boost
            }
        }

        // Boost important chunks
        if (metadata.ContainsKey("importance_score"))
        {
            var importance = (int)metadata["importance_score"];
            result.Score *= (1 + (importance / 50.0)); // Up to 20% boost for score 10
        }
    }

    return results.OrderByDescending(r => r.Score).ToList();
}
```

## Performance Considerations

### Cost Analysis

**Traditional Chunking:**
- Cost: $0 (no LLM calls)
- Speed: Instant (synchronous)

**Agentic Chunking (per document):**

**Analysis Phase:**
- 1 LLM call per document (or per section if large)
- Input: Document text (~2000 chars avg)
- Output: Boundaries JSON (~500 tokens)
- Model: gpt-4o-mini
- Cost: ~$0.0003 per document

**Metadata Phase (optional):**
- 1 LLM call per chunk (parallel)
- Input: Chunk text (~1000 chars avg)
- Output: Metadata JSON (~200 tokens)
- Cost: ~$0.0001 per chunk

**Example: 10-page technical document**
- Document size: 20,000 chars
- Analysis: 1 call → $0.0003
- Chunks: ~15 chunks
- Metadata: 15 calls → $0.0015
- **Total: ~$0.0018 per document**

**Cost Optimization:**
- Use gpt-4o-mini (80% cheaper than gpt-4o)
- Enable caching (reuse analysis for unchanged docs)
- Make metadata generation optional
- Use hierarchical chunking for large docs

### Speed Analysis

**Agentic Chunking Latency:**

| Phase | Latency | Parallelizable? |
|-------|---------|-----------------|
| Analysis | 2-5 sec | No (sequential) |
| Metadata (per chunk) | 1-3 sec | Yes (parallel) |
| Total (15 chunks) | 3-8 sec | With parallel metadata |

**Optimization Strategies:**

1. **Parallel Metadata Generation:**
   ```csharp
   await Task.WhenAll(chunks.Select(c => EnrichSingleChunkAsync(c)));
   ```
   Reduces metadata phase from 15-45 sec → 1-3 sec

2. **Background Processing:**
   ```csharp
   // Store chunks immediately, enrich metadata in background
   _ = Task.Run(() => EnrichChunksWithMetadataAsync(chunks));
   ```

3. **Caching:**
   ```csharp
   // Cache analysis results by content hash
   var hash = SHA256(text);
   if (cache.TryGet(hash, out var analysis)) return analysis;
   ```

4. **Streaming:**
   ```csharp
   // Return chunks as they're generated (IAsyncEnumerable)
   await foreach (var chunk in ChunkStreamAsync(text, options))
   {
       yield return chunk;
   }
   ```

### Scalability

**Small Documents (<2K chars):**
- Analysis: 1 call
- Chunks: ~2-3
- Time: 2-4 seconds
- Cost: ~$0.0006

**Medium Documents (2K-10K chars):**
- Analysis: 1 call
- Chunks: ~5-10
- Time: 3-6 seconds
- Cost: ~$0.0013

**Large Documents (>10K chars):**
- Analysis: Hierarchical (1 call per 2K section)
- Chunks: 15-30
- Time: 5-10 seconds
- Cost: ~$0.003

**Very Large Documents (>50K chars):**
- Consider pre-splitting by chapter/section
- Process sections independently
- Merge results
- Time: 10-30 seconds
- Cost: ~$0.01-0.02

### Migration Tool

```csharp
public class ChunkingMigrationTool
{
    public async Task MigrateDocumentAsync(string documentId, ChunkingStrategy newStrategy)
    {
        // 1. Load existing document
        var doc = await _documentStore.GetDocument(documentId);

        // 2. Re-chunk with new strategy
        var chunker = new TextChunker(_llmClient);
        var options = new TextChunkingOptions { Strategy = newStrategy };
        var newChunks = await chunker.ChunkTextAsync(doc.Content, options);

        // 3. Delete old chunks
        await _documentStore.DeleteChunks(documentId);

        // 4. Store new chunks
        await _documentStore.StoreChunks(documentId, newChunks);

        // 5. Re-generate embeddings (if needed)
        if (options.UseAgenticMetadata)
        {
            await _embeddingService.RegenerateEmbeddings(documentId);
        }
    }

    public async Task MigrateAllDocumentsAsync(ChunkingStrategy newStrategy, IProgress<int> progress)
    {
        var allDocIds = await _documentStore.GetAllDocumentIds();

        for (int i = 0; i < allDocIds.Count; i++)
        {
            await MigrateDocumentAsync(allDocIds[i], newStrategy);
            progress.Report((i + 1) * 100 / allDocIds.Count);
        }
    }
}
```
