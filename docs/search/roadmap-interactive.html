Hazina Cognitive Search Roadmap

Interactive Implementation Plan - 4 Phases, 8 Weeks

Total Duration
8 Weeks
Total Phases
4 Phases
Current Progress
85%
Team Size
2-3 Engineers
  • ▶
    Phase 1: REST API Foundation Weeks 1-2
    Duration: 2 weeks (40 hours/engineer) • Team: 2 engineers
    Goal: Build production-ready REST API to expose existing search capabilities via HTTP endpoints.
    • ▶
      Task 1.1: Project Setup & Infrastructure Days 1-2
      Effort: 16 hours (2 days × 2 engineers)
      • ▶
        Subtasks
        • Create new project Hazina.API.Search
        • Set up ASP.NET Core 9.0 with minimal API or controllers
        • Configure dependency injection
        • Add Swashbuckle for Swagger/OpenAPI
        • Set up Serilog for structured logging
        • Configure CORS policies
        • Add health check endpoints
      • ▶
        Deliverables
        • Running API project with /health and /swagger endpoints
        • Structured logging to console and file
        • Dependency injection configured
      • ▶
        Acceptance Criteria
        • dotnet run starts API on https://localhost:5001
        • GET /health returns 200 OK with status
        • GET /swagger shows interactive API documentation
        • Logs are written to console and logs/api-.log
    • ▶
      Task 1.2: Core Search Endpoints Days 3-4
      Effort: 16 hours (2 days × 2 engineers)
      • ▶
        Subtasks
        • Create SearchController
        • Implement POST /api/v1/search/query (natural language)
        • Implement POST /api/v1/search/semantic (vector similarity)
        • Implement POST /api/v1/search/hybrid (vector + graph)
        • Create request/response DTOs
        • Add input validation
        • Map RAGEngine results to API responses
        • Add error handling and logging
    • ▶
      Task 1.3: Document Endpoints Days 5-6
      Effort: 16 hours (2 days × 2 engineers)
      • ▶
        Subtasks
        • Create DocumentsController
        • Implement GET /api/v1/documents (list with filtering)
        • Implement POST /api/v1/documents/upload (file upload)
        • Implement GET /api/v1/documents/{id} (retrieve by ID)
        • Implement PUT /api/v1/documents/{id} (update metadata)
        • Implement DELETE /api/v1/documents/{id} (soft delete)
        • Implement GET /api/v1/documents/{id}/similar (find similar)
        • Add multipart form-data support for uploads
        • Add pagination for list endpoint
    • ▶
      Task 1.4: Authentication & Security Days 7-10
      Effort: 32 hours (4 days × 2 engineers)
      • ▶
        Subtasks
        • Implement JWT Bearer token authentication
        • Add API key authentication (for service-to-service)
        • Configure authorization policies
        • Add rate limiting (AspNetCoreRateLimit)
        • Add request logging middleware
        • Add exception handling middleware
        • Configure HTTPS and HSTS
        • Add CORS policies
        • Security headers (X-Frame-Options, X-Content-Type-Options, etc.)
        • Write integration tests
  • ▶
    Phase 2: NLP Enhancements Weeks 3-4
    Duration: 2 weeks (40 hours/engineer) • Team: 2 engineers
    Goal: Add key phrase extraction, sentiment analysis, and advanced OCR to enrich document processing.
    • ▶
      Task 2.1: Key Phrase Extraction Days 11-13
      Effort: 24 hours (3 days × 2 engineers)
      • ▶
        Subtasks
        • Create Hazina.AI.KeyPhraseExtraction project
        • Implement IKeyPhraseExtractor interface
        • Implement LLMKeyPhraseExtractor (uses existing LLM providers)
        • Implement TfIdfKeyPhraseExtractor (statistical)
        • Implement HybridKeyPhraseExtractor (combines both)
        • Add configuration options
        • Write unit tests
        • Integrate with DocumentStore
        • Add API endpoint: POST /api/v1/documents/{id}/keyphrases
        • Add automatic key phrase extraction to document upload
    • ▶
      Task 2.2: Sentiment Analysis Days 14-16
      Effort: 24 hours (3 days × 2 engineers)
      • ▶
        Subtasks
        • Create Hazina.AI.SentimentAnalysis project
        • Implement ISentimentAnalyzer interface
        • Implement LLMSentimentAnalyzer
        • Implement VaderSentimentAnalyzer (lexicon-based)
        • Implement AspectBasedSentimentAnalyzer
        • Add emotion detection (joy, anger, sadness, fear, etc.)
        • Write unit tests
        • Integrate with DocumentStore
        • Add API endpoint: POST /api/v1/documents/{id}/sentiment
        • Add sentiment as searchable metadata
    • ▶
      Task 2.3: Advanced OCR Integration Days 17-20
      Effort: 32 hours (4 days × 2 engineers)
      • ▶
        Subtasks
        • Create Hazina.AI.OCR project
        • Implement IOCREngine interface
        • Implement TesseractOCREngine (open-source)
        • Implement AzureComputerVisionOCR (cloud)
        • Implement HybridOCREngine (Tesseract first, cloud fallback)
        • Add image preprocessing (grayscale, contrast, deskew)
        • Add PDF page-to-image conversion
        • Write unit tests
        • Integrate with BinaryDocumentProcessor
        • Add API endpoint: POST /api/v1/ocr/extract
        • Update document upload to use OCR for images/PDFs
  • ▶
    Phase 3: GraphQL API Weeks 5-6
    Duration: 2 weeks (40 hours/engineer) • Team: 2 engineers
    Goal: Add GraphQL API for flexible, client-driven queries and real-time subscriptions.
    • ▶
      Task 3.1: Schema Design & Project Setup Days 21-22
      Effort: 16 hours (2 days × 2 engineers)
      • ▶
        Subtasks
        • Create Hazina.API.GraphQL project
        • Add HotChocolate dependencies
        • Design GraphQL schema (types, queries, mutations)
        • Define root Query type
        • Define root Mutation type
        • Define root Subscription type
        • Add GraphQL Playground
        • Configure in-memory query cache
        • Set up DataLoader for N+1 prevention
        • Write schema documentation
    • ▶
      Task 3.2: Query & Mutation Resolvers Days 23-25
      Effort: 24 hours (3 days × 2 engineers)
      • ▶
        Subtasks
        • Implement Query.search resolver
        • Implement Query.document and Query.documents resolvers
        • Implement Query.entities and Query.entity resolvers
        • Implement Mutation.uploadDocument resolver
        • Implement Mutation.updateDocument resolver
        • Implement Mutation.deleteDocument resolver
        • Add field resolvers for nested data (e.g., Document.similar)
        • Implement DataLoaders to prevent N+1 queries
        • Add error handling
        • Write integration tests
    • ▶
      Task 3.3: Real-Time Subscriptions Days 26-28
      Effort: 24 hours (3 days × 2 engineers)
      • ▶
        Subtasks
        • Configure WebSocket support
        • Implement Subscription.documentUploaded
        • Implement Subscription.documentUpdated
        • Implement Subscription.searchCompleted
        • Add event publishing from API
        • Add subscription filtering
        • Write subscription integration tests
        • Add client example (JavaScript)
  • ▶
