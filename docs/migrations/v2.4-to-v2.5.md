# Migration Guide: v2.4.x → v2.5.0

**Breaking changes:** None — v2.5.0 is backwards-compatible with v2.4.x.

This guide covers infrastructure and configuration changes you may want to adopt.

---

|---------|---------|

| Package | Change |

## Adopting JWT Authentication (Optional)

If you run Hazina Orchestration in production, add authentication:

```json
// appsettings.json
{
  "Jwt": {
    "Key": "<your-secret-key-min-32-chars>",
    "Issuer": "hazina-orchestration",
    "Audience": "hazina-clients",
    "ExpiryMinutes": 60
  }
}
```

```csharp
// Program.cs
builder.Services.AddHazinaJwtAuth(builder.Configuration);

app.UseAuthentication();
app.UseAuthorization();
```

No JWT configuration means the server starts without auth (development default).

## Adopting WebSearch (Optional)

```bash
dotnet add package Hazina.Tools.Services.Web --version 2.5.0
```

```csharp
using Hazina.Tools.Services.Web;

var searchTool = new WebSearchTool(new WebSearchConfig
{
    BingApiKey = Environment.GetEnvironmentVariable("BING_API_KEY")!
});

var results = await searchTool.SearchAsync("Hazina framework .NET", maxResults: 5);
```

## NuGet Publishing Changes

The `publish-all.ps1` script now uses a simplified two-step workflow:

1. Build all packages: `dotnet pack -c Release`
2. Push to NuGet: iterates `nupkgs/` directory

If you maintain a fork with custom publish scripts, align with the new pattern in `publish-all.ps1`.
